# 03. FAQ

**Q. 小さな修正でも毎回 spec が要る？**
A. 要りません。Tier 0 は不要、Tier 1 は軽量specのみ。ブランチ名（`t0/`・`t1/`）と PRラベルで宣言します。ただし Issue は Tier 0 でも作ります。

**Q. hooks を消せば強制を回避できるのでは？**
A. できます。hooks はローカルの速い注意喚起にすぎません。**本当の門番は CI** で、こちらはバイパスできません。

**Q. 実装を Cursor/Copilot でやりたい。**
A. それが前提の設計です。設計担当エージェント（superpowers必須）が作った `specs/<feature>/` を契約として渡せば、どのagentでも実装できます。

**Q. 人間はどこで関わる？**
A. 最初の質問（Tier と仕様の不明点）、問い合わせ（AC を削る・弱める必要があるときなど、条件に当たるときだけ）、PR のレビューとマージの 3 つです。spec の承認は独立したエージェント `spec-reviewer` が行い、AI はマージしません。

**Q. 実装中に spec の不備に気づいたら？**
A. 実装を止めて、依頼したエージェントに報告します。実装フェーズで勝手に再設計しないでください。依頼した側が spec を直して spec レビューを受け直すか、問い合わせの条件に当たれば人間に問い合わせます。

**Q. submodule の更新はどう配る？**
A. `git submodule update --remote` で各プロジェクトが追従します。破壊的変更はタグ（semver）で管理します。
